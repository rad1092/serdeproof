# Security and limitations

SerdeProof launches **trusted local adapter code with your operating-system account's privileges**. The separate JVM prevents dependency collisions and helps contain accidental hangs. It is not an OS sandbox. Adapters can read files, use the network, spawn processes and access inherited environment variables. Run only adapters you reviewed; use an isolated CI worker/container with minimal credentials for sensitive applications.

The runner uses argument arrays, never shell interpolation. Explicit classpath paths and JVM arguments are configuration, not untrusted remote input. A malicious adapter or JVM option can defeat process supervision. Descendant cleanup is best effort: detached descendants and platform restrictions cannot be reliably controlled by portable Java APIs. A timeout bounds normal I/O and execution, not CPU/memory allocation or JVM startup blocked by the OS. Use external OS resource limits where required.

Fixture/configuration bytes, stdout, stderr and adapter response fields are bounded. The manifest, corpus size, fixture count, parser depth and difference count have limits. Limits fail the run instead of silently marking it compatible. Some failure modes, including kernel hangs or forcibly killing the parent process, remain outside JVM control. Cancellation via Java interruption and ordinary CLI termination requests cleanup; SIGKILL or power loss cannot run cleanup hooks.

Default JSON/JUnit reports omit payload values, fixture filenames, absolute paths, adapter exception messages and stderr. IDs and pointers are hashed. `--details` intentionally reveals IDs, field names and rule reasons, but still omits values and exception text. Content fingerprints reveal equality; low-entropy values may be guessed by hashing candidates. Treat reports and corpus files according to your data policy even in default mode. The runner does not upload configuration or fixture contents. Trusted adapters can access the network with the user's privileges. The optional development audit script queries only public dependency coordinates.

Observations are authored by you. An omitted field, incorrect canonicalization, time-dependent mapper, nondeterministic module or unrepresentative corpus can hide defects. Date/enum hints label differences and do not establish equivalence. JSON number lexical differences are reported independently of numeric value. Object member order and insignificant JSON whitespace are intentionally ignored in structural comparison; array order remains significant. This tool does not validate signature formats, arbitrary non-JSON payloads, streaming concurrency, transport headers, Java native serialization or application business invariants.

Reports are repeatable for fixed inputs, date and environment; JVM/OS differences are recorded, so cross-platform report bytes may differ. Expected-change rules require exact fixture, pointer, kind and direction, with reason and expiry. Rules cannot waive infrastructure failures. An expired, unused or invalid rule fails the run so it cannot silently outlive its justification.

Some JDK 17 builds fail before application startup when the calling application's `-cp` path contains supplementary Unicode characters such as emoji. Keep the CLI/library caller's installation path on an ordinary path on those JDKs. SerdeProof's adapter launcher uses URI manifest entries and is tested with Korean, spaces and emoji in adapter JAR paths. Fixture and report paths can contain Unicode. This does not repair bugs in the JVM that starts the caller.

Dependency checks cover known public advisories at a recorded time, and upstream license declarations; they cannot prove absence of unknown vulnerabilities. Releases include checksums for transfer integrity and are **unsigned and not notarized**. This project does not claim a security certification or Maven Central publication.

For a suspected vulnerability, use GitHub's private vulnerability reporting if available on the repository, or contact the maintainer privately before publishing sensitive details. Never attach production payloads, credentials or raw adapter logs to a public issue. Release 0.1 receives fixes on the main branch; no commercial support or response-time guarantee is offered.
